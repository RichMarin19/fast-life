# Weight Tracker Enterprise Audit – 2025-11-07 (Codex)

**Overall readiness:** **6.2 / 10.** Security primitives (secure storage, sanitized crash logging) and concurrency tests are strong, but the Phase 2 privacy/observability envelope and Slice 3B Progress Story polish remain incomplete. Singletons still creep into new DI surfaces, observability stops at local signposts, and Progress Story UI diverges from Apple HIG (localization + accessibility).

## Strengths
- **Main-actor Weight stack + telemetry hooks.** WeightManager instruments add/delete/sync flows with WeightTrackerMetrics (FastingTracker/Core/Managers/WeightManager.swift:120-206, 407-508) and routes failures through CrashReportManager, giving us deterministic timelines for CRUD work.
- **Crash logging is privacy-aware.** CrashTelemetrySanitizer enforces redaction of weight/goal/BMI tokens across nested payloads and is unit-tested (FastingTracker/Core/Managers/CrashReportManager.swift:370-503, FastingTrackerTests/Managers/CrashTelemetrySanitizerTests.swift:6-104).
- **AppLogger guardrails.** AppLoggerPrivacyTests crawl every Swift file to block stray `.public` logs, literal weight units, and direct Crashlytics imports (FastingTrackerTests/Infrastructure/AppLoggerPrivacyTests.swift:3-134), plugging a frequent privacy regression source.
- **Concurrency validation exists.** WeightManagerThreadSafetyTests hammer concurrent add/delete/sync scenarios via async task groups (FastingTrackerTests/ThreadSafety/WeightManagerThreadSafetyTests.swift:33-200), proving the secure persistence layer survives HealthKit bursts.
- **Slice 3B telemetry entry points.** WeightTrendsViewModel emits hide/reorder/opt-out metrics plus trend-state snapshots (FastingTracker/UI/Components/WeightProgressStory/WeightTrendsViewModel.swift:129-254), so the data model is ready once downstream dashboards exist.

## Gaps & Risks (highest impact first)
1. **Observability data never leaves the device.** WeightTrackerMetrics only writes DEBUG logs and `os_signpost` events (FastingTracker/Core/Managers/Weight/WeightTrackerMetrics.swift:8-107); there is no bridge to MetricKit, Firebase custom events, or even persisted aggregates. Progress Story KPIs (card reorder volume, opt-out rate, trend snapshot availability) cannot be trended over time, which blocks Phase 2 OKRs around observability dashboards.
2. **Dependency injection is still half-finished.** WeightTrendsViewModel defaults to `ContentOptOutManager.shared` and `ProgressStoryCards.shared` (WeightTrendsViewModel.swift:32-38), and WeightControlCenterCoordinator/PreferencesViewModel do the same (FastingTracker/Core/ViewModels/Weight/WeightControlCenterCoordinator.swift:34-49, PreferencesViewModel.swift:45-53). Tests cannot inject mocks without touching global state, and production code keeps mutable singletons alive—contradicting the Phase 2 DI plan logged in HANDOFF.md.
3. **Progress Story UI violates Apple HIG basics.** The screen still relies on `NavigationView` (deprecated on iOS 16+) and hard-coded English copy (“Your LIFe Journey”, “Trend Snapshot”, “Progress you can feel…”) (WeightTrendsView.swift:92-151, WeightProgressStoryCardStack.swift:173-190, WeightProgressStoryMetricsProvider.swift:45-93). Without `LocalizedStringKey` and `NavigationStack`, we cannot certify localization or multi-window compliance.
4. **Accessibility for drag-only reordering is missing.** ProgressStoryCardStack exposes only drag-and-drop gestures; the drag handle is hidden from VoiceOver and there are no `.accessibilityAction(.increment/.decrement)` fallbacks (WeightProgressStoryCardStack.swift:132-159). VoiceOver users therefore cannot reorder cards—an App Store rejection risk for accessibility regressions.
5. **Privacy harness lacks runtime enforcement.** AppLoggerPrivacyTests rely on regex search, but nothing asserts that `AppLogger.infoPublic` or CrashReportManager custom values stay sanitized at runtime. For example, WeightControlCenterCoordinator restores data without any logging tests, and WeightTrendsViewModel metadata (“card”: rawValue) flows straight to `WeightTrackerMetrics.recordProgressStoryEvent` without a privacy classification. We need integration tests or build scripts that parse the generated `.logarchive` to ensure `.private` defaults hold.
6. **Progress Story logic still references legacy card inventory.** `ProgressStoryCardType` keeps coach bar/banners/did-you-know cases even though UX signaled upcoming retirements (FastingTracker/UI/Views/WeightControlCenterModels.swift:86-149). Without pruning cases and migrations, Manage-My-Experience toggles list ghost cards and opt-out IDs remain inconsistent, complicating Slice 3B sign-off.

## Apple HIG & SwiftUI Alignment
- **Positive:** UI components use DS tokens, Reduce Motion is honored for the animated background (WeightTrendsView.swift:88-151), and destructive actions follow alert patterns (WeightControlCenterView.swift:120-205).
- **Negative:** Navigation still relies on `NavigationView`, toolbar buttons are custom rather than `toolbar` modifiers, large textual banners are not localized, and drag handles do not expose VoiceOver reorder actions. Apple’s HIG also expects carousels with visible “Edit” affordances; Progress Story cards silently enter drag mode with no focus cues.

## Next Critical Improvements (before new feature work)
1. **Finish DI retrofit.** Thread `ContentOptOutManaging`, `ProgressStoryCardManaging`, and persistence dependencies through WeightTrendsView/Coordinator/PreferencesViewModel initializers and previews so tests can inject mocks and singletons can be deprecated. Add protocol registries under `Core/Protocols` and update CompositionRoot.
2. **Ship real observability plumbing.** Extend WeightTrackerMetrics to send summarized events to MetricKit/Firebase (e.g., `MXSignpostMetric`, Crashlytics custom keys) and capture distribution aggregates (p50/p95 durations, error rates). Pair with a doc/runbook entry describing how to inspect these metrics.
3. **Localization + NavigationStack sweep for Progress Story.** Replace literals with `LocalizedStringKey`, break copy into `.stringsdict`, and migrate the screen to `NavigationStack` with `toolbar` APIs. This also enables multi-scene support and preps us for right-to-left layouts.
4. **Accessibility + interaction parity.** Add `.accessibilityAction` handlers for reordering, expose hide buttons via `accessibilityCustomActions`, and provide focusable status indicators so VoiceOver users can consume the narrative without drag gestures.
5. **Telemetry & privacy tests.** Add unit/UI tests that assert metrics fire (e.g., ViewModel spy verifying `WeightTrackerMetrics.recordProgressStoryEvent` on hide/reorder) and extend AppLoggerPrivacyTests to inspect compiled log archives or run the app with `OS_ACTIVITY_MODE`. Block CI when new files introduce `.public` or reference `Crashlytics` directly.
